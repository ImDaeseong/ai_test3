# Verification

```powershell
cd app
npm run typecheck
npm test
npm run build
npm run test:e2e
```

## 필수 검증

- 지원 사이트(잡코리아·사람인·인크루트) 허용 URL과 거부 URL, http·타 호스트 거부, 인크루트 `www`→`job` 재작성
- import 충분성은 분석기 readiness(`inspectJobDescription`)에 위임한다: 요건 마커만으로는 불충분(인식 스킬 없으면 붙여넣기 안내), 상세 iframe 추출 성공만으로 `sufficient`를 강제하지 않는다
- 요약만 수집(sufficient=false) 시 분석 필드를 채우지 않고 회사·제목만 안내하며 상세 요강 붙여넣기를 요구
- `분석하기`는 readiness(분석 가능한 스킬 존재)일 때만 활성화; 아니면 사유별 안내(길이 부족 vs 요건 없음)
- 무매칭(강한 매칭 0) 시 원인별 배너 표시(공고 스킬 0 vs 이력서 불일치)
- import readiness ↔ 실제 분석 결과 정합: ready면 요건 추출>0, notready면 0 (`data/*.json`로 확인)
- 공개 HTML에서 한글 제목·회사명·본문 추출
- 후보자 JSON 첨부, 잘못된 JSON 거부, 새로고침 복원
- 분석 요청 스키마와 결과 스키마, 미니 프로젝트 정확히 3개
- OpenAI `generate()` 경로: 모킹으로 파싱→null 제거→스키마 검증(키·비용 없이)
- 프롬프트 인젝션 방어 및 비요구사항 문단 제외 규칙
- 검증 JSON 생성, 동일 (입력+결과) 중복 방지, 경로 이탈 차단, 누적은 분석 품질과 무관
- 프로덕션 빌드와 주요 브라우저 흐름
- 브라우저 렌더-DOM 경로(직접 복사/북마클릿) 안내가 표시된다 (docs/BOOKMARKLET.md)

## 분석 품질 검토

`data/*.json`에서 입력과 결과를 함께 확인한다.

- 없는 경험을 만들지 않았는가
- 필수와 우대를 구분했는가
- 점수와 설명이 입력 근거와 일치하는가
- 약점, 프로젝트와 면접 질문이 실제 공고에 연결되는가
- 반복 실행 시 중대한 결과 변동이 없는가

## 알려진 후속 작업

- `분석하기` 게이팅과 import 충분성은 현재 **로컬 분석기의 스킬 사전** 기준이다. `OPENAI_API_KEY`를
  연결하면 LLM은 사전에 없는 요건도 분석할 수 있으므로, 그때는 클라이언트에 "LLM 구성됨" 여부를
  노출해 readiness 게이트를 완화해야 한다(현재 미구현 — 키 연결 시 함께 처리).
- 이미지로 등록된 공고는 텍스트 추출이 불가하다. 현재는 readiness 불충분→붙여넣기 안내로 폴백하며,
  OCR은 도입하지 않았다(도입 시 의존성 실사 선행).

## HOLD 조건

- 로그인, CAPTCHA 또는 접근통제 우회가 필요함
- 실제 후보자 데이터가 로그나 외부 서비스로 의도치 않게 노출됨
- 저장 파일이 프로젝트 `data` 밖에 생성됨
- 같은 검증 항목이 세 번 연속 실패함
- 유료 API 사용 전 로컬 검증 데이터가 충분히 검토되지 않음
