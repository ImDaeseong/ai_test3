# CareerDiff

잡코리아·사람인·인크루트 채용공고와 후보자 경력을 비교해 적합도, 부족한 역량, 이력서 개선안,
보완 프로젝트와 면접 준비 계획을 만드는 로컬 웹앱입니다.

## 실행

`run-careerdiff.cmd`를 더블클릭하면 서버가 시작되고 기본 브라우저에서
`http://localhost:3000`이 열립니다.

직접 실행하려면:

```powershell
cd app
npm install
npm run dev
```

## 사용

1. 공고의 상세 모집요강을 복사해 채용공고 입력란에 붙여넣습니다(가장 정확한 주 경로).
   보조로 잡코리아·사람인·인크루트 상세공고 URL을 넣어 `공고 가져오기`를 쓸 수 있으나, 사이트에
   따라 요약만 수집되면 그 사실이 표시되고 상세 요강 붙여넣기를 안내합니다.
2. 이력서/커리어/프로젝트 설명을 붙여넣거나, JSON 파일을 첨부합니다.
3. `분석하기`를 누릅니다(공고·이력서가 각 30자 이상이면 활성화됩니다. 인식된 스킬이 없으면 결과가
   제한적일 수 있다는 안내가 함께 표시됩니다).
4. 화면 결과와 JSON을 확인합니다. 부족한 기술은 모두 "연관 기술 가이드"에 나타나며, 다른 기술과
   연결된 항목은 그 관계와 이유를 함께 보여줍니다(예: RAG는 Vector DB·LangChain과 연결, 직접 연결이
   없으면 최대 3단계까지 이어지는 간접 경로도 찾아 제시합니다). 연결된 기술이 없는 항목은 그 기술을
   직접 학습·실습하라는 안내를 받습니다.

분석 검증 케이스는 `data/<UUID>.json`에 누적됩니다. 이 기록은 결과 검토용이며 누적되어도 분석
품질이 올라가지는 않습니다. 파일에는 채용공고와 후보자 프로필 원문이 포함되므로 외부 공유 전에
개인정보를 확인해야 합니다. 이 누적 기록은 계속 커지므로 메인 화면에서는 자동으로 불러오지
않고, 우측 상단 "분석 히스토리 보기" 링크(`/history`)에서 원할 때만 목록으로 훑어보고 클릭해
다시 열어볼 수 있습니다.

후보자 프로필을 JSON 파일로 저장해뒀다가 반복 첨부하려면, 파일명을 `candidate-profile-*.json`
패턴으로 두면 저장소 루트 `.gitignore`가 자동으로 커밋에서 제외합니다. 전화번호·이메일·주소는
스킬 매칭 분석에 쓰이지 않으므로(텍스트 기술 키워드만 비교) `"전화번호"`, `"메일주소"`, `"주소"` 같은
자리표시자로 채워도 분석 결과에 영향이 없습니다 — 파일을 실수로 공유하거나 커밋해도 개인정보가
노출되지 않도록 저장 시점부터 이렇게 채우는 걸 권장합니다.

## 현재 분석 방식

- `OPENAI_API_KEY`가 없으면 입력 공고와 후보자 프로필을 실제로 분석하는 로컬 키워드 분석기(`LocalAnalysisProvider`)를 사용합니다.
- 키가 있으면 OpenAI Structured Outputs를 사용합니다. 안정화 이전에는 키를 연결하지 않고 Claude
  Code에서 로컬 분석기를 반복 개선합니다(자세한 방침은 [구조와 보안](docs/ARCHITECTURE.md) 참고).
- 채용공고 수집(공고 가져오기)은 지원 사이트의 공개 상세 페이지 HTML만 직접 읽으며 로그인, CAPTCHA
  또는 접근통제를 우회하지 않습니다.
