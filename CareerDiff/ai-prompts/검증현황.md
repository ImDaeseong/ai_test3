# Prompt / AI-Feature Verification Registry

이 문서는 CareerDiff 안에서 **유료 API 비용이 들거나, 실데이터를 다루는 모든
AI 의존 기능**을 한곳에 모아, 각각이 "무료/로컬 검증을 통과했는지"를 추적하는 단일 레지스트리다.

별도의 `VERIFICATION.md` 게이트 로그 파일은 존재하지 않는다 — 실행 결과/게이트 로그는 이 문서의
각 행 "현재 상태" 셀에 직접 기록한다. (과거 문서에 `VERIFICATION.md`를 참조하는 문구가 있었다면
이 문서로 통합된 것으로 간주한다.)

## 핵심 원칙

> **유료 API 비용이 드는 기능이든, 실데이터를 다루는 기능이든, "완벽하게 검증"되기 전까지는
> 반드시 무료/저비용 경로(웹 UI 프로젝트, 로컬 mock, 소량 수동 실행)로 먼저 확인한다. 검증
> 통과 기록이 없으면 유료/실전 경로로 전환하지 않는다.**

예: 채용정보 수동 수집(`job-collection-manual/`)은 Claude/ChatGPT 웹 Project로 무료 검증한다.
채용공고-이력서 적합도 분석(`/api/analyze`)은 과거엔 같은 방식(웹 Project)을 썼으나 2026-08-01
사용자가 로컬 검증으로 전환했다(1번 행 참고) — "무료"의 형태는 기능마다 다를 수 있고, 핵심은
"검증 통과 기록 없이 유료/실전 경로를 켜지 않는다"는 원칙 자체다. 이 문서는 이 원칙을 CareerDiff
전체의 모든 AI 의존 기능에 동일하게 적용하기 위한 목록이다.

## 게이트 종류

| 게이트 종류 | 의미 | 무엇을 막는가 |
| --- | --- | --- |
| 비용 게이트 (💰) | 실행할 때마다 유료 API 요금이 발생 | 검증 안 된 프롬프트로 돈을 쓰는 것 |
| 안전성 게이트 (🔒) | 무료 API/공개 데이터라도 실데이터·개인정보·ToS 리스크가 있음 | 검증 안 된 채로 실데이터가 자동화(스케줄)에 들어가는 것 |

## 새 AI 기능을 추가할 때

새로운 프롬프트/모델 호출/실데이터 API를 추가하면, 코드를 작성하기 *전에* 이 표에 행을 하나
추가한다 — 트리거, 게이트 종류, 무료 검증 경로, 전환 조건을 먼저 정의하고 나서 구현한다
(`AGENTS.md`의 "구현 전 목적·보안 경계·검증 기준·HOLD 조건을 먼저 정의" 원칙과 동일).
